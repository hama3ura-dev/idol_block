著作権フリーのブロック崩し（スマホ版・3ステージ） 使い方
==========================================
画像などを差し替えて再配布OKです。
Claud Codeを使って生成しており著作権はフリーです。

この文章も含めて全てパックされた物が以下からダウンロードできますので
自由に変更してください。
https://hama3ura-dev.github.io/idol_block/idol_block.zip


このファイルは、ゲームの遊び方と、難易度の調整や画像・音の差し替えをしたい人向けの説明です。
画像や効果音・BGM をプログラムで作り直したい人は、option フォルダの readme2.txt を見てください。


■ ファイル構成
  block_attack\
    index.html    … ゲーム本体（スマホ向けの縦長画面。PC でもマウスで遊べます）
    favicon.ico   … ブラウザのタブに出るアイコン
    ogp.png       … SNS でリンクを貼ったときに出るサムネイル画像（OGP 画像、1200×630）
    readme.txt    … このファイル
    image\        … 画像
      block1a.png   … ステージ1 龍崎薫	屋外				1122×960
      block1b.png   … ステージ1 龍崎薫 ブロックを崩すと見える絵	1122×960
      block1c.png   … ステージ1 サムネイル（ステージセレクト用）	561×480
      block2a.png   … ステージ2 佐々木千枝　高級クラブ			1122×960
      block2b.png   … ステージ2 佐々木千枝 ブロックを崩すと見える絵    1122×960
      block2c.png   … ステージ2 サムネイル                        	 561×480
      block3a.png   … ステージ3 赤城みりあ　ホテル			1122×960
      block3b.png   … ステージ3 赤城みりあ ブロックを崩すと見える絵	1122×960
      block3c.png   … ステージ3 サムネイル				561×480
      clear.png     … 3ステージすべてクリアしたときのご褒美画面	1206×2622
    se\           … 効果音
      start.mp3     … タイトル画面で「スタート」ボタンを押したときの音
      start2.mp3    … ステージ開始のフレーズ
      brick.mp3     … ボールがブロックに当たった音
      paddle.mp3    … ボールがパドルに当たった音
      wall.mp3      … ボールが壁・天井に当たった音
      miss.mp3      … ミスしたときの音
      clear.mp3     … ステージクリアのジングル（ステージ1・2・3共通）
      allclear.mp3  … 3ステージすべてクリアしたときのジングル
    bgm\          … BGM
      stage1.mp3    … ステージ1（ロック / 120 BPM）
      stage2.mp3    … ステージ2（ロック / 140 BPM）
      stage3.mp3    … ステージ3（ロック / 170 BPM・一番速い）
      stage1b.mp3 / stage2b.mp3 / stage3b.mp3
                    … 上の3曲のアップテンポ版（138 / 161 / 195 BPM）。
                      ブロックが残り少なくなると切り替わる
    option\       … 画像・効果音・BGM・アイコンを作り直すためのスクリプト（説明は readme2.txt）

  ※ ゲームに必要なのは index.html・favicon.ico・ogp.png と image / se / bgm フォルダです。
    option フォルダは無くても動きます。
    se / bgm フォルダが無い場合は、音が鳴らないだけでゲームは遊べます。


■ 遊ぶには
  ・スマホ：Web サーバー（GitHub Pages など）に置いて、そのアドレスをブラウザで開きます。
    スマホではファイルを直接開いても動かないので、必ず Web サーバーに置いてください。
  ・PC：index.html をダブルクリックしても遊べます（Web サーバーに置いたものを開いても OK）。


■ ゲームの流れ
  1. ステージセレクト画面で、1・2・3 のどのステージからでも選べます（カードをタップ）。
     スタートのフレーズ（start.mp3）が鳴り、鳴り終わると BGM が始まります。
  2. タップで発射。ブロックを崩していきます。
     ・ブロックが残り 10 個になると、BGM がアップテンポ版に切り替わります。
     ・ミスしても BGM は続きます。
  3. ブロックを全部崩すと STAGE CLEAR!（clear.mp3 が鳴ります）
     ・スコアはそのまま次のステージに引き継ぎます。
     ・ボール（残機）が1個増えます。
     ・ボールのスピードが少し遅くなってから次のステージが始まります。
  4. ステージセレクト画面に戻るので、まだクリアしていないステージを選びます。
     クリアしたステージには「CLEAR!」が付き、もう選べません。
  5. 3ステージすべてクリアすると allclear.mp3 が鳴り、ご褒美画面（clear.png）が
     画面いっぱいに表示され、画面下に最終スコアが出ます。タップでタイトルに戻ります。
  6. 途中で残機が0になると GAME OVER。タップすると最初から
     （スコア0・クリア記録もリセット）やり直しです。


■ 操作
  ・スマホ：画面を左右になぞるとパドルが動き、タップで発射。
    パドルの下の、うっすら色が付いた場所（「ここを左右になぞって操作」と書いてあるあたり）を
    なぞると、指でボールが隠れず遊びやすいです。
  ・マウス：動かすとパドルが動き、クリックで発射。
  ・スマホでは画面がスクロールしたり拡大したりしないようにしてあります。


■ 画面の見方（プレイ中）
  ・1行目：左にスコア、右に残機（白い丸）。
  ・2行目：左に今のステージ、右に SPEED メーター（緑 → 黄 → 赤 の順に速い）。
  ・上の段のブロックほど高得点です（最上段100点 ～ 最下段10点）。


■ 音について
  ・スマホは最初にタップするまで音を出せない決まりなので、最初のタップから音が出ます。
  ・iPhone はマナーモード（消音スイッチ）にしていると音が鳴らないことがあります。
  ・スマホを別のアプリに切り替えると音は止まり、戻ると再開します。
  ・Web サーバーに置いたときは、BGM がつなぎ目なしでループします。
    PC で index.html をダブルクリックして開いたときは別の方法で鳴らすので、
    BGM のつなぎ目がごくわずかにずれることがあります。


==========================================
ここから下は、設定を変えたい人向けです。
設定は index.html の先頭付近にある CONFIG にまとまっています。
index.html をメモ帳などで開き、数字や文字を書き換えて保存してください（文字コードは UTF-8 のまま）。
==========================================

■ 難易度の調整
  残機
    lives             … 最初の残機（初期値 3）
    livesBonusOnClear … ステージクリアで増える残機（初期値 1）

  ボールのスピード（単位：ピクセル/秒、整数で指定）
    speedStart            … 最初のスピード（初期値 320）
    speedMax              … 最高スピード（初期値 800）
    speedUpPerBrick       … ブロックを1個壊すごとに速くなる量（初期値 5）
    speedUpPerPaddle      … パドルで打ち返すごとに速くなる量（初期値 3）
    speedUpPerCeiling     … 天井で跳ね返るごとに速くなる量（初期値 4）
    speedDownOnMiss       … 残機を1つ失ったときに遅くする量（初期値 90）
    speedDownOnStageClear … ステージをクリアして次へ進むときに遅くする量（初期値 100）

  ・スピードは speedStart ～ speedMax の範囲に収まります。
  ・スピードはステージをまたいで引き継ぎ、クリア時に speedDownOnStageClear だけ遅くなります。
  ・ミスすると「今のスピード」から speedDownOnMiss だけ遅くなります。
  ・ブロックが減って天井まで抜けるようになると、加速が一気に早まります。
  ・SPEED メーターは speedStart で空、speedMax で満タンになります。
  ・難しく感じたら speedMax や各 speedUp～ を小さく、簡単すぎたら大きくしてください。

  パドル
    paddleFromBottom  … パドルの位置（画面の下端からの距離。初期値 200）
                        大きくするほどパドルが上になり、下の指を置く場所が広くなりますが、
                        ボールがパドルに届くまでの時間が短くなる（少し難しくなる）ので注意。

  BGM の切り替え
    fastBgmAtBricksLeft … 残りのブロックがこの数以下になったら、
                          アップテンポ版の BGM に切り替える（初期値 10）


■ 画像の差し替え
  image フォルダの画像を、同じ名前の画像で置き換える（上書きする）だけでステージの絵が変わります。
  画像が見つからないときは、色付きのブロックや色の四角で代わりに表示されます。

  名前のルール
    block[ステージ番号][a / b / c].png
      a … 最初の絵（ブロックの絵）
      b … ブロックが崩れたときに下から見える絵
      c … ステージセレクト画面に出すサムネイル
    例：block2b.png ＝ ステージ2 の崩した後の絵
    clear.png … 3ステージすべてクリアしたときのご褒美画面

  大きさ
    ・ブロックは横6列 × 縦10段 = 60個。1個は約62×32ピクセルの横長です。
    ・ブロック領域は 374×320 で、画面の上半分くらいを使います。
    ・a / b の画像はこの領域と同じ縦横比（374:320）で作ると、切り取られずに表示されます。
      くっきり表示させるには 3倍の 1122×960 がおすすめです。
    ・c（サムネイル）も同じ縦横比がおすすめです（例：561×480）。
    ・clear.png は縦画面いっぱい（1206×2622）に表示します。
      縦横比が違う画像は、はみ出た部分が切り取られます。
      画面の一番下（約50ピクセル分）には最終スコアが重なって表示されます。

  関係する設定（CONFIG）
    stages      … ステージの名前と説明（ステージセレクトに表示）
    imageDir    … 画像を置くフォルダ（初期値 "image/"）
    clearImage  … ご褒美画面の画像（imageDir の中。初期値 "clear.png"）


■ 音の差し替え・音量
  se / bgm フォルダの mp3 を、同じ名前の mp3 で置き換えると音が変わります。

  関係する設定（CONFIG）
    sound             … false にすると音を鳴らさない（初期値 true）
    seVolume          … 効果音の音量 0.0～1.0（初期値 1.0）
    bgmVolume         … BGM の音量 0.0～1.0（初期値 1.0）
    se                … 効果音のファイル（start / brick / paddle / wall / miss / clear / allclear）
    bgm               … ステージ1・2・3 の BGM
                          file / bpm         … ふだんの曲とそのテンポ
                          fastFile / fastBpm … アップテンポ版の曲とそのテンポ
                          bars               … 小節数
    bgmGapAfterStart  … スタートのフレーズが鳴り終わってから BGM が始まるまでの間（初期値 0.2 秒）
    bgmLoopStart      … ループの開始位置（初期値 0.1 秒。MP3 の先頭の無音をとばすため）

  ・BGM は「1周の長さ = bars × 4拍 × 60 ÷ bpm 秒」でループします。
    曲を差し替えるときは、その曲の bpm と bars に合わせてください。
  ・付属の BGM は、つなぎ目なしでループさせるため、ファイルの最後に曲の頭が 0.5 秒ついています。
    自分で用意した曲に差し替えるときも、同じように作るとつなぎ目がきれいになります。
    （曲の頭を付けていない場合は、つなぎ目で少し音が途切れたり重なったりします）


■ アクセス数を数える（Google アナリティクス）
  何人が遊びに来たかなどを、Google アナリティクスで数えられます。
  数えた結果は、Google アナリティクスの管理画面で、権限のある Google アカウントでログインした人
  （管理者）だけが見られます。ゲームの画面にはカウンターなどは何も表示されません。

  設定（CONFIG）
    analyticsId … Google アナリティクスの「測定 ID」（G- で始まる番号）。初期値 ""（数えない）

  始め方
    1. https://analytics.google.com/ を開き、Google アカウントでログインして「測定を開始」。
    2. アカウント名（例：block_attack）→ プロパティ名（例：BLOCK ATTACK）を入力。
       タイムゾーンは「日本」、通貨は「日本円」にします。
    3. ビジネスの情報などを答えたあと、データの収集で「ウェブ」を選び、
       ウェブサイトの URL に hama3ura-dev.github.io/block_attack/ 、ストリーム名に BLOCK ATTACK を入れて作成。
    4. 表示された「測定 ID」（G-XXXXXXXXXX）をコピーします。
       （「タグの実装手順」が表示されても、自分でタグを貼る必要はありません）
    5. index.html の CONFIG の analyticsId に貼り付けて保存し、GitHub に公開します。
         analyticsId: "G-XXXXXXXXXX",

  見方
    ・Google アナリティクスの左のメニュー「レポート」→「リアルタイムの概要」で、
      今遊んでいる人の数がすぐ見られます（自分のスマホで開いて試せます）。
    ・「レポート」→「エンゲージメント」→「ページとスクリーン」で、表示回数や人数が見られます。
      リアルタイム以外のレポートは、反映まで 1 日ほどかかることがあります。
    ・ほかの人にも見せたいときは、「管理」→「プロパティのアクセス管理」で Google アカウントを追加します。

  注意
    ・自分の PC で試しているとき（localhost や、index.html をダブルクリックして開いたとき）は数えません。
    ・Google アナリティクスは Cookie を使います。Google の利用規約では、サイトで
      Google アナリティクスを使っていることを知らせることが求められています。
      必要に応じて、公開ページの説明などに一言書いておいてください。


■ SNS でリンクを貼ったときの表示（OGP）
  X（旧 Twitter）・Facebook・LINE などにゲームのアドレスを貼ると、
  ogp.png の画像とタイトル・説明文がカードのように表示されます。
  設定は index.html の先頭の <head> の中にある meta タグです（CONFIG ではありません）。

    og:title / og:description / description … タイトルと説明文。content="…" の中を自由に書き換える
    og:url    … 公開しているアドレス（https://hama3ura-dev.github.io/idol_blockk/）
    og:image  … OGP 画像の完全なアドレス（https://hama3ura-dev.github.io/idol_block/ogp.png）

  ・別の場所で公開するときは、og:url と og:image をそのアドレスに書き換えてください。
    （https:// から始まる完全なアドレスでないと、SNS が画像を見つけられません）
  ・ogp.png を自分の画像に差し替えるときは 1200×630 で作り、大事なものは真ん中に置いてください。
    LINE などでは真ん中が正方形に切り取られて表示されることがあります。
  ・SNS は一度読んだ内容をしばらく覚えているので、変えてもすぐには反映されないことがあります。
    Facebook は「シェアデバッガー」で読み直しができます。


■ 画面の大きさの設定
  width / height    … ゲーム画面の大きさ（初期値 402 / 874）
  rows / cols       … ブロックの段数・列数（初期値 10 / 6）
  brickHeight       … 1段の高さ（初期値 32）
  brickAreaTop      … ブロック領域の上端の位置（初期値 66）
  sideMargin        … 左右の余白（初期値 14）

  ・iPhone 18 Pro（6.3インチ、1206×2622 ピクセル、3倍表示）を想定し、
    ゲーム画面は 402×874（論理ピクセル）で作っています。
  ・実際の描画は端末の画素密度に合わせて高解像度（iPhone なら 1206×2622）で行うので、
    文字や絵がにじみません。
  ・画面の大きさが違う端末や PC では、縦横比を保ったまま画面に収まるよう拡大・縮小されます。
